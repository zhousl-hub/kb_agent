一、项目概述

KBA（Tongyuan Knowledge Base System） 是一套面向企业的 LLM 知识库与智能助手平台，采用 RAG（检索增强生成） 范式，支持 Chatbot、Workflow、Agent 三类 AI 应用形态。

架构上采用「企业中台 + AI 引擎」分层：外层 KBA（Java 微服务 + Vue 门户）提供多租户、SSO、审计、知识空间管理；内层 Dify 作为统一的 RAG & Agent 引擎，负责文档索引、混合检索、重排序、LLM 推理与工具编排。

十二、权限系统详细设计

KBA 权限体系采用 RBAC（角色访问控制）为主、ABAC（属性访问控制）为辅、多租户隔离为底 的三层模型。认证统一由 Sa-Token + Redis 管理会话，网关层校验登录态并向下游注入用户上下文；授权在菜单/API/数据三个维度分层控制，关键操作写入审计日志。

十四、面试问答记忆卡

Q1：你们的 RAG 是怎么做的？

以 Dify 为 RAG 引擎。离线阶段通过 Celery 触发 IndexingRunner，完成文档抽取、切分、Embedding 写入 Qdrant；在线阶段用户提问时 DatasetRetrieval 根据应用绑定的 dataset_ids 执行混合检索，经 Rerank 后构建 DocumentContext 注入 LLM Prompt，返回答案和 citation 引用。KBA 负责企业门户和会话持久化，通过 WebClient 代理 Dify 流式 API。

Q2：Agent 和 Chatbot 有什么区别？

Chatbot 模式每次自动做 RAG 检索；Agent 模式由 LLM 通过 ReACT 循环自主决定是否调用知识库 Tool、搜索 Tool 或 API Tool，适合多步推理。两者底层检索都走 DatasetRetrieval，Agent 多了工具编排层。

Q3：为什么不用 Dify 单独部署，还要 KBA？

Dify 擅长 AI 能力，KBA 补企业级需求：Keycloak SSO、Sa-Token 网关鉴权、多租户知识空间、审计日志、统一门户 UI、业务元数据管理。本质是「Dify = AI 引擎，KBA = 企业外壳」。

Q4：流式对话怎么实现的？

KBA 用 Spring WebClient 调 Dify /v1/chat-messages，response_mode=streaming，返回 Flux 逐 chunk 转发前端 SSE；同时解析 JSON 提取 conversation_id 和 answer 片段，流结束后完整持久化到 MySQL。

Q5：混合检索怎么工作？

RetrievalService 用 ThreadPoolExecutor 并行执行 Embedding 语义检索和全文检索，结果去重后交给 DataPostProcessor，按 Rerank 模型或加权分数融合排序，取 top_k 构建上下文。

Q6：权限系统怎么设计的？

RBAC 为主：用户通过 sys_user_role 关联多个角色，角色通过 sys_role_permission 关联权限码（如 knowledge:document:upload）。认证用 Sa-Token 签发 Bearer Token 存 Redis，Gateway 的 SaReactorFilter 全局 checkLogin，AuthGlobalFilter 向下游注入 X-User-Id 和 X-Tenant-Id。前端 Pinia 存 permissions 数组，路由守卫调 hasPermission。数据级用 tenant_id 租户隔离 + StpUtil.getLoginIdAsLong() 校验资源归属。SSO 走 Keycloak OIDC。关键操作写 audit_log。

Q7：Dify RAG 离线索引和在线检索分别经过哪些步骤？

离线：Celery document_indexing_task → IndexingRunner.run 四步：① _extract（ExtractProcessor 按 PDF/Word/HTML/URL 解析）② _transform（CleanProcessor 清洗 + TextSplitter 切分）③ _load_segments（写 PostgreSQL segment）④ _load（high_quality：CacheEmbedding + Vector→Qdrant；economy：jieba 关键词）。在线：DatasetRetrieval.retrieve 元数据过滤 + 多库路由 → RetrievalService._retrieve 并行语义/全文/混合 → DataPostProcessor Rerank → DocumentContext + citation 注入 LLM。详见 §7.5。
