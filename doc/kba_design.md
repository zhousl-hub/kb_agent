# TYKB 企业级知识库系统定制化设计（支持 Dify 多应用扩展）

## 1. 项目目标与定位

**TYKB** 面向企业内部与行业场景构建统一知识能力，并通过标准化插件与服务层扩展，为 **Dify 提供可复用、可治理、可观测的多应用知识服务能力**。核心目标如下：

1. 统一知识资产管理：覆盖文档、FAQ、结构化数据、业务系统数据流。
2. 统一检索与推理能力：支持关键词检索、向量检索、混合召回、重排与可追溯回答。
3. 统一多应用供给：一套知识底座服务多个 Dify 应用（客服、销售助手、研发助手、运营 Copilot 等）。
4. 统一治理与安全：提供权限、审计、版本、生命周期管理与合规能力。

---

## 2. 总体架构设计

系统采用“**五层一中心**”架构：

### 2.1 接入层（Ingestion Layer）

- 数据源连接器：
  - 部门上传门户：各部门人员通过统一上传入口提交文件（支持拖拽、批量、模板化元数据）。
  - 外网导入通道：通过 URL 抓取、外部站点导入、受控代理下载方式导入公开或授权外部资料。
  - 文档源：PDF、Word、PPT、Markdown、HTML、Confluence、Notion。
  - 协作与IM：钉钉、飞书、企业微信。
  - 业务系统：CRM、工单系统、ERP、OA。
  - 数据库：MySQL / PostgreSQL / ClickHouse。
- 接入方式：
  - 人工上传（按部门、项目、密级归档）
  - 外网导入（URL/站点级采集，含白名单与安全审计）
  - 批量导入（全量）
  - 增量同步（CDC / 定时任务）
  - 实时 webhook 触发
- 预处理：OCR、版式还原、表格抽取、去重、脱敏、语言检测、恶意内容扫描。

### 2.2 知识处理层（Knowledge Processing Layer）

- 文档切分：按语义段落、标题层级、表格单元、代码块切分。
- 元数据增强：来源、作者、时间、部门、业务域、密级、版本号。
- 实体与关系抽取：人物、组织、产品、流程节点、术语字典。
- 标签体系：自动标签 + 人工标签 + 规则标签。
- 质量评分：完整性、时效性、可信度、引用频次。

### 2.3 存储与索引层（Storage & Index Layer）

- 对象存储：原始文档与解析后中间文件。
- 关系存储：知识元数据、权限、审计日志、工作流状态。
- 向量存储：多模型 embedding 向量库（可按租户隔离）。
- 全文检索：倒排索引支持关键词快速召回。
- 知识图谱（可选）：实体关系网络用于高级推理。

### 2.4 检索与编排层（Retrieval & Orchestration Layer）

- 混合检索：BM25 + 向量召回 + 业务规则召回。
- 查询改写：意图识别、同义词扩展、拼写纠错。
- 多路召回：按知识域/部门/权限并行检索。
- 重排策略：Cross-Encoder 重排 + 业务规则加权。
- 上下文构建：动态窗口、去冗余、证据优先。
- 回答策略：
  - RAG 回答
  - 带引用回答
  - 不确定性回退（转人工/澄清提问）

### 2.5 应用与开放层（Application & Open API Layer）

- Dify 插件适配器：
  - 统一知识检索 API
  - 多应用知识空间映射
  - Prompt 模板管理
  - 工具调用（Tool Use）
- 应用模板：
  - 智能客服（FAQ + 工单知识）
  - 销售助手（产品资料 + 竞品情报）
  - 运营助手（SOP + 报表口径）
  - 研发助手（API 文档 + 代码规范）
- 大模型管理中心：统一接入本地模型、国内主流模型、国际主流模型，支持模型路由、密钥托管、成本与限流控制。
- 开放接口：REST / gRPC / Webhook / SDK。

### 2.6 治理中心（Governance Center）

- 权限模型：RBAC + ABAC（按角色、部门、标签、数据密级控制）。
- 审计与追踪：查询日志、回答证据、用户行为链路。
- 质量看板：命中率、召回率、用户满意度、幻觉率。
- 生命周期管理：草稿、发布、冻结、归档、废弃。
- 统一身份认证：支持对接企业 OAuth2/OIDC 身份系统（Keycloak），实现 SSO 单点登录与统一会话管理。

## 3. 面向 Dify 的扩展设计

## 3.1 扩展目标

通过 **TYKB 中台**向 Dify 提供“可配置的知识能力包”，让不同应用可按场景组合能力，而不是重复建设知识库。

## 3.2 核心扩展模块

1. **Dify-Knowledge Gateway**
   - 向 Dify 暴露统一检索接口。
   - 支持应用级别路由（按 app_id 映射知识空间）。
   - 支持 Token 透传与细粒度权限校验。

2. **Prompt & Policy Engine**
   - 按应用维护系统提示词模板、回答风格、引用策略。
   - 配置“是否必须引用来源”“是否允许推测回答”“是否触发澄清问题”。

3. **RAG Pipeline Composer**
   - 提供可视化/配置化流水线：Query Rewrite -> Retrieve -> Rerank -> Synthesize。
   - 支持不同应用选择不同策略（客服偏精准，创新助手偏发散）。

4. **App Knowledge Space Manager**
   - 支持一个应用绑定多个知识空间。
   - 支持同一知识空间被多个应用共享，并按字段级权限隔离。

5. **Feedback Loop Service**
   - 接收 Dify 用户反馈（有用/无用/纠错）。
   - 将反馈回写到知识质量模型，自动优化召回与重排策略。

## 3.3 Dify 集成模式

- 模式 A：作为 Dify 外部工具（Tool）接入。
- 模式 B：作为 Dify 知识检索后端（替代默认知识检索）。
- 模式 C：混合模式（简单应用用默认检索，关键应用走 TYKB 增强检索）。

## 3.4 Dify 大模型管理设置（新增）

- 模型接入范围：
  - 本地模型：vLLM / Ollama / TensorRT-LLM / 私有化推理集群。
  - 国内模型：通义千问、文心、豆包、智谱、Kimi 等。
  - 国际模型：OpenAI、Anthropic、Google Gemini、Mistral、Meta Llama 服务化版本等。
- 接入方式：
  - OpenAI-Compatible API
  - 云厂商原生 API 适配器
  - 私有网关代理（支持内网穿透与审计）
- 核心能力：
  - 模型注册与版本管理（model_id、provider、region、context_length、tool_call 能力）
  - 多模型路由策略（按应用、场景、成本、时延、可用性进行动态路由）
  - 回退机制（主模型失败自动降级到备选模型）
  - Key 与凭证管理（KMS 托管、定期轮换、最小权限）
  - 配额与限流（租户级、应用级、用户级）
  - 成本治理（token 成本看板、预算阈值告警、分摊报表）

## 4. 关键功能清单（按模块）

## 4.1 知识接入功能

- 多源连接器管理
- 部门上传工作台（上传模板、元数据必填校验、批量导入）
- 外网导入控制台（域名白名单、爬取深度、导入审批流）
- 同步任务编排（全量/增量/实时）
- 数据清洗、脱敏、去重
- 同步失败重试与告警

## 4.2 报告编辑与知识回写功能

- 双栏协同界面：左侧在线富文本编辑器，右侧知识库检索面板。
- 检索插入能力：右侧检索结果可一键插入左侧编辑区，并自动适配当前光标所在富文本格式（字号、样式、段落级别）。
- 编辑增强：支持引用块、图表、表格、脚注、来源链接、模板片段复用。
- 实时保存：按秒级自动保存草稿，支持断线恢复。
- 版本管理：每次自动保存形成历史版本，支持版本对比、回退、分支编辑与发布版锁定。
- 知识回写：编辑完成文档可直接入库，自动触发切分、向量化、索引更新并关联作者/部门/版本元数据。
- 协作与权限：支持多人协同、评论批注、审批发布与密级控制。

## 4.3 知识加工功能

- 智能切分策略中心
- 元数据标准化
- 术语与同义词词库管理
- 质量评分与人工校对工作台

## 4.4 检索与问答功能

- 多策略检索（关键词/语义/混合）
- 上下文构建策略
- 可解释引用输出（片段 + 来源 + 时间）
- 多轮对话记忆与会话隔离

## 4.5 Dify 应用支撑功能

- 应用级知识空间配置
- 应用级 Prompt 模板
- 应用级检索策略模板
- 应用级 SLA 与限流策略

## 4.6 Dify 大模型管理功能

- 模型供应商管理（本地/国内/国际）
- 模型连接配置（Endpoint、API Key、组织、区域、超时、重试）
- 模型能力标签（推理能力、上下文长度、函数调用、多模态支持）
- 路由与回退策略配置（优先级、成本优先、质量优先、时延优先）
- 安全控制（密钥脱敏展示、权限分级、调用审计）
- 成本与容量管理（配额、预算、告警、并发上限）

## 4.7 统一登录与账号体系功能（OAuth + Keycloak）

- SSO 单点登录：统一接入公司账号体系，免二次登录访问平台。
- OAuth2/OIDC 授权：支持授权码模式（Authorization Code + PKCE）与服务间客户端凭证模式。
- 组织与角色同步：从 Keycloak 同步用户、部门、角色组并自动映射权限。
- 会话与令牌管理：Access Token/Refresh Token 生命周期控制、强制下线、设备会话审计。
- 安全策略：MFA（可选）、登录风控、异常登录告警、IP 白名单。
- 审计留痕：登录、登出、授权失败、越权访问全量记录。

## 4.8 治理与运维功能

- 权限与密级管理
- 审计日志中心
- 质量评估与 A/B 测试
- 成本监控（Embedding、检索、LLM 调用）

## 5. 多租户与安全设计

1. 租户隔离
   - 数据库逻辑隔离 + 向量索引隔离 + 对象存储路径隔离。
2. 传输与存储安全
   - 全链路 TLS、静态加密、KMS 密钥托管。
3. 数据权限
   - 用户 -> 角色 -> 资源 -> 操作的四层授权链。
4. 合规能力
   - 敏感词识别、PII 脱敏、数据留存策略、删除可追溯。
5. 统一认证与鉴权（OAuth + Keycloak）
   - 基于 OIDC 标准接入 Keycloak，支持 SSO 登录、Token 刷新、会话注销。
   - 支持从 IdP 同步组织架构、用户组与角色，映射到系统 RBAC/ABAC 权限模型。
   - 支持应用侧 Token 透传到 Dify/网关服务进行端到端鉴权。

## 6. 非功能需求设计

- 高可用：核心服务多副本，检索链路降级可用。
- 高性能：
  - P95 检索时延 < 800ms（不含 LLM 生成）
  - 并发支持按租户弹性扩展。
- 可观测性：
  - Metrics（QPS、延迟、命中率）
  - Logs（请求链路）
  - Tracing（检索与生成分段追踪）
- 可维护性：配置中心化、流水线版本化、灰度发布。

## 7. 典型业务流程

## 7.1 知识入库流程

1. 连接器采集数据。
2. 文档解析与清洗。
3. 切分与元数据增强。
4. 向量化与索引构建。
5. 审核发布到对应知识空间。

## 7.2 应用问答流程（Dify 调用）

1. Dify 传入问题与 app_id。
2. Gateway 校验权限并路由知识空间。
3. Query Rewrite 与多路召回。
4. Rerank + 上下文构建。
5. LLM 生成并附引用。
6. 返回答案与证据，记录日志与反馈。

## 7.3 报告编辑与知识回写流程

1. 用户在左侧富文本编辑器新建或打开报告。
2. 右侧输入检索问题，从知识库返回候选片段与来源。
3. 用户将片段插入当前光标位置，系统继承当前富文本样式。
4. 编辑过程实时自动保存，形成连续版本快照。
5. 用户可对任意版本进行对比并回退。
6. 报告发布后自动写入知识库，进入审核/发布流程并参与后续检索。

## 8. 成功指标（KPI）建议

- 知识检索命中率 > 85%
- 有引用回答占比 > 95%
- 用户满意度（Thumbs Up）> 80%
- 幻觉率下降 30%+
- 新应用接入时间从“周级”降到“天级”
